Суть метода в том, чтобы подменить системный бинарный файл на скрипт, который сначала запускает вредоносный код, а затем - оригинальное приложение. Можно создать такой бэкдор для всех приложений в системе, программы будут запускаться как обычно, без подозрений, но при этом в фоне будет запущен reverse shell 
<img width="974" height="416" alt="image" src="https://github.com/user-attachments/assets/60830431-9ed5-45a2-a014-369eb967f4c9" />

Создание скрипта, который подменяет оригинальный файл и записывает в него вредоносный код. Сначала выполняется вредоносный скрипт, работающий в фоне без вывода информации об этом процессе, потом оригинальная программа с сохранением всех аргументов (“\$@”) 

<img width="974" height="80" alt="image" src="https://github.com/user-attachments/assets/82362673-07fa-4d5f-a0b9-d22009163a97" />
Срабатывание reverse shell при запуске команды ls и открытии firefox. Также на прослушиваемом порту открывается оболочка с правами пользователя, выполнившим команду, поэтому это также может быть root.

<img width="974" height="95" alt="image" src="https://github.com/user-attachments/assets/ecd0c2b2-27a5-43a1-832a-825c1cc455c0" />

Вывод:
Метод сложно обнаружить без особой проверки, так как сам скрипт срабатывает только при открытии определенных приложений или утилит, в остальное время он неактивен. Однако если сделать ошибку в коде или если скрипт запустится 2 раза подряд это может сломать системные утилиты (оригинальный файл перезапишется), и для их восстановления придется обновлять поврежденные файлы.

<img width="974" height="90" alt="image" src="https://github.com/user-attachments/assets/293fe925-8374-4760-b820-05d6c69d7fd8" />

Скрытность:
•	Системы контроля целостности файлов заметят изменение хеша измененных бинарных файлов.
•	Администратор может заметить подозрительный процесс-обертку в списке задач (например, через ps aux).

Rootkit – это тип вредоносных программ, предназначенных для предоставления злоумышленникам доступа к целевому устройству и контроля над ним. Хотя большинство руткитов влияют на работу программного обеспечения и операционную систему, некоторые из них могут также поразить оборудование и прошивку компьютера. Руткиты способны скрывать свое присутствие, но даже в этот период они активны. Руткиты работают поблизости или внутри ядра операционной системы, что дает им возможность отправлять команды компьютеру. Все объекты, использующие операционную систему, являются потенциальной целью для руткитов.
Руткиты режима ядра представляют самую серьезную угрозу, поскольку нацелены на ядро операционной системы. Злоумышленники используют их не только для доступа к файлам на компьютере, но и для изменения функций операционной системы, путем добавления собственного кода.

Примечание
Перед началом реализации данного метода нужно обозначить, что на используемой ВМ отключена безопасная загрузка - функция прошивки UEFI, гарантирующая запуск только подписанных доверенных загрузчиков и ядер, что защищает от руткитов и вредоносного ПО при загрузке. 
<img width="783" height="217" alt="image" src="https://github.com/user-attachments/assets/ceb599b3-77dd-45f6-9d67-4be9dc900e33" />
Однако, на большинстве современных систем эта функция активна и для начала ее нужно отключить. Поэтому если нет возможности отключить безопасную загрузку через BIOS/UEFI, нет root прав, или  не использовать уязвимость загрузчика для обхода проверки подписи (Boothole), то rootkit становится бесполезным ( модуль не загрузится ). 
Пример простого варианта для отключения secure boot через подпись модуля и регистрации его в UEFI ( нужны права root ):
•	Сгенерировать ключи с помощью openssl
•	Подписать модуль созданным ключом 
•	Добавить созданный сертификат в доверенные с помощью mokutil
•	Зарегистрировать ключ при перезагрузке в MOK manager ( нужен физический доступ )
После этого руткит сможет загрузится даже с включенной безопасной загрузкой.

Стек технологий для реализации данного метода:
•	Язык C - все модули ядра пишутся на C
•	Заголовочные файлы ядра (linux-headers) - необходимы для компиляции модуля
•	Компилятор (gcc, make) - стандартные средства сборки
•	Makefile - для автоматизации компиляции
•	Ftrace (Function Tracer) - фреймворк для трассировки и отладки ядра Linux

Вывод:
Ошибки в модуле ядра, особенно в рутките, с высокой вероятностью приводят к kernel panic, зависанию системы, повреждению данных или уязвимостям. Основные источники ошибок - некорректная работа с памятью, неправильные прототипы ftrace-функций, неверная фильтрация буферов и отсутствие восстановления состояния после выгрузки. Для минимизации рисков необходимо тщательное тестирование в изолированной среде и применение защитных механизмов (проверка указателей, сохранение оригинальных адресов, использование safe-функций.
Для современных версий ядра есть множество мер защиты. Запрет на загрузку неподписанных модулей ядра (module_sig_enforce), что предотвращает внедрение руткитов. KASLR (Kernel Address Space Layout Randomization): Рандомизация размещения ядра в оперативной памяти при каждой загрузке. Это усложняет атакующим предсказание адресов функций ядра. Защита от записи (WP-бит) в sys_call_table.
Для обхода этих мер защиты был использован фреймворк ftrace для трассировки и отладки ядра Linux. Ключевая особенность ftrace, которую используют руткиты это его возможность динамически подключать свои callback функции к началу или концу любой другой функции ядра и таким образом можно перехватывать выполнение функций, благодаря этому можно обойтись без модификации sys_call_table.
kprobe - брейкпоинт на входе функции или любой ее инструкции (позволяет получить значения аргументов исполняемой функции). Использовали динамический поиск адресов через цепочку kprobe → kallsyms_lookup_name(). Это позволяет найти их в памяти каждый раз заново.

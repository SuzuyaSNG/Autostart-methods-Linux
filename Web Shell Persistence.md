этот метод относится к технике Server Software Component: Web Shell. Web shell  это вредоносный скрипт, который размещается на веб-сервере жертвы и позволяет злоумышленнику выполнять произвольные команды на хосте через обычные HTTP-запросы. В отличие от reverse shell, где инициатором соединения выступает жертва, здесь инициатива принадлежит злоумышленнику. Его ключевая особенность - создание собственного легковесного веб-сервера (на PHP или Python) для обслуживания web shell.
CGI (Common Gateway Interface) — это стандартный протокол, который позволяет веб-серверу выполнять внешние программы (скрипты) для генерации динамического контента.
Обычно веб-сервер просто отдаёт статические файлы (HTML, картинки). Но если он настроен на обработку CGI, то при запросе определённого скрипта (например, shell.cgi) сервер запускает его как отдельный процесс, передаёт ему входные данные (параметры URL, заголовки, тело POST-запроса), а затем получает от скрипта готовый HTTP-ответ и отправляет его клиенту (браузеру или атакующему).

cgi - модуль для работы с данными, переданными через веб-запрос (GET/POST параметры). Его основная задача -  парсить входящие параметры от клиента.
Переменная form хранит аргументы переданные через запрос ( например ?cmd=id ).
os.popen(cmd): Этот вызов выполняет переданную команду cmd на целевой системе и открывает виртуальный файловый объект, через который можно прочитать её вывод.

Примечание:
Сервер python обрабатывает CGI-скрипты только из стандартных поддиректорий cgi-bin/
Вывод:
•	Фоновый запуск и отсоединение от терминала: Команда nohup позволяет запущенному процессу веб-сервера пережить завершение сеанса пользователя, гарантируя постоянную доступность web shell.
•	Маскировка под легитимный трафик: web shell доступен через стандартные HTTP-запросы (GET), что позволяет легко маскировать вредоносную активность под обычный веб-трафик.
•	Анализ запущенных процессов: Команда ps -aux | grep -E "python -S|http.server" покажет запущенные в фоне легковесные серверы. Это самый прямой и надёжный способ обнаружения.
•	Мониторинг сетевой активности: Команда ss -tlnp отобразит приложения, прослушивающие порты. Появление подозрительного слушающего сервера (особенно от имени обычного пользователя) на таких портах, как 8080, является серьёзным индикатором компрометации.
•	Анализ файловой системы: Обнаружение скриптов cmd.php или cmd.py в нестандартных местах, таких как /tmp, /var/tmp, /tmp/cgi-bin или home-директории пользователя, является тревожным сигналом.
